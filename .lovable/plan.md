# 校园局域网部署下的材料导出：可行性与优化

## 结论：方案可以继续用

导出全过程只发生在「浏览器 ↔ 你自己的服务器」之间：

- 网页从数据库读出这批学生的申请、姓名班级、文件位置；
- 向你自己部署的文件服务申请临时下载地址，把文件取回电脑；
- 在浏览器里就地打包成压缩包并保存。

不访问任何境外服务，不依赖外部网盘或 CDN，所以校园内网、没有外网出口也能用。只有一个前提：文件服务的访问地址必须是校内能解析到的地址（和大家打开系统用的是同一个域名/IP），而不是外网地址。这一点会写进部署说明并加一个自检提示。

## 现在的薄弱点

- 几百份材料时全部内容先堆在浏览器内存里再压缩，容易卡顿甚至失败；
- 单个文件下载失败只跳过，不重试，失败清单只在提示里一闪而过；
- 图片本来已经压缩过，再压一遍几乎不省空间，却白白多花很多时间；
- 导出过程中误关页面就前功尽弃；
- 一个一个申请临时地址，请求次数多。

## 优化内容

1. **自动分卷**：按班级顺序累积，超过约 1.2 GB 或 600 个文件就先落一个压缩包，继续下一卷，文件名带「第 1 卷 / 第 2 卷」。一个班的材料不会被拆到两卷里。
2. **失败自动重试**：每个文件最多重试 2 次（间隔递增）；仍失败的记进压缩包里的「导出失败清单.txt」，并在页面上列出，支持一键「只重试失败项」。
3. **压缩方式按类型区分**：图片、PDF、压缩包直接存储不再压缩，Excel 等文本类正常压缩。速度显著提升，体积几乎不变。
4. **批量申请下载地址**：一次申请 100 个文件的临时地址，减少请求往返，内网弱网下更稳。
5. **并发自适应**：默认 6 路并发，连续失败自动降到 2 路，恢复后回升。
6. **更清楚的进度**：显示「第几卷 / 已完成 x / 共 y 个文件 / 已用时 / 预计剩余」，可随时「停止导出」，已完成部分仍可保存。
7. **防误关**：导出期间离开页面会弹出确认提示。
8. **导出前体检**：开始前先试取一个文件，若失败直接提示「文件服务在当前网络下不可访问，请检查内网地址配置」，避免跑到一半才发现。

## 技术细节

- 文件：`src/pages/admin/WindowExport.tsx`（教师入口与路由已存在，不改动）。
- 新增 `src/lib/zipExport.ts`：封装分卷累积、`createSignedUrls` 批量签名、带指数退避的 `fetchWithRetry`、自适应并发的 `mapLimit`、`generateAsync` 分卷输出。
- 压缩策略：按扩展名决定 `{ compression: "STORE" }`（jpg/jpeg/png/webp/gif/pdf/zip/rar/7z）或 `DEFLATE level 6`。
- 分卷阈值：`MAX_BYTES = 1.2e9`、`MAX_FILES = 600`，以 signed URL 响应的 `blob.size` 累加判断；每卷生成后释放引用以便回收内存。
- 停止导出用 `AbortController` 传入 `fetch`。
- `beforeunload` 仅在 `exporting === true` 时绑定。
- 连通性体检复用 `createSignedUrl` + `HEAD`/`Range: bytes=0-0` 请求。
- 不改数据库、不改后端、不新增依赖。
